## 2. Что мы строим

MVP **AI-системы электронного документооборота закупок** для фарма-компании полного цикла. Задание от руководства Ольги.

**Срок:** 1,5 дня (~36 часов). **Деплой обязателен.** Полный текст ТЗ — в `документация/тз.md` проекта.

**Что должно работать:**
- 7 типов документов (заявка, КП, протокол выбора, договор, спецификация, акт, счёт-фактура)
- Единая карточка сделки + связи с поставщиком и контрактом
- Workflow согласования по типу + сумме
- Версионирование с возможностью сравнения
- AI-извлечение полей из вставленного текста
- AI-семантический поиск
- AI-выявление задержек согласования
- AI-проверка комплектности
- Дашборд (на согласовании / просрочки / комплектность)

**Прикладываем по ТЗ:** ссылку на работающее приложение, репозиторий с историей коммитов, README.md, PROMPTS.md.

## 3. Зафиксированные решения (не пересматривать без серьёзных оснований)

| Решение | Зафиксировано как |
|---|---|
| **Архитектура:** модульный монолит | ADR-0003 + явный анализ времени (микросервисы съедают 7-9 часов сверху) |
| **Стек:** FastAPI + Next.js + PostgreSQL + pgvector | ADR-0001 |
| **LLM:** OpenRouter (у Ольги ключ с балансом $90) | ADR-0002 |
| **Модели:** гибрид Claude Sonnet 4.5 (масса задач) + Opus 4.6 (только сравнение версий) + OpenAI text-embedding-3-small | ADR-0002 |
| **Идентификаторы в коде:** кириллица (имена модулей, файлов, переменных, колонок БД) | соглашение с Ольгой |
| **Имена env-переменных:** ASCII (всё-таки стандарт инструментария) | соглашение |
| **Изоляция модулей:** отдельные Postgres-схемы на модуль, cross-schema joins запрещены | ADR-0003 + ревью Ольги |
| **AI-вызовы:** документ всегда сохраняется первым, AI в try/except, при сбое статус `ai_ожидает_повтора` | ревью Ольги (критично — не убирать) |
| **Audit trail:** append-only таблица `события` с middleware-записью на каждой мутации | ревью Ольги |
| **Демо:** 2 сделки покрывают все 7 функц + 4 AI требования ТЗ | ребалансировка после ревью |
| **GitHub:** через GitHub Desktop у Ольги | соглашение |
| **Safety-протокол кодогенерации:** обязателен, см. `safety/протокол.md` + `safety/чек-лист-перед-коммитом.md` | требование Ольги |

## 5. Рабочее соглашение

- **Ольга беспокоится о квоте Claude.ai.** Пиши плотно, без воды. Если хочешь сделать большой блок — предупреди заранее.
- **Каждый блок кода** сопровождай: что делает (3-7 пунктов) + риски + чек-лист для Ольги + следующее действие.
- **Никаких placeholder-ов** (`...`, `TODO`, `should exist`, `assume`). Только исполняемый код.
- **Все импорты должны существовать.** Прежде чем написать `from x import y` — убедись, что `y` реально есть в `x`.
- **LLM в коде = только через `app.общее.llm_client`.** Никогда напрямую из модулей.
- **БД в коде = модуль ходит только в свою схему.** Никаких cross-schema joins.
- **Idempotency** на действиях согласования (Idempotency-Key заголовок).
- **Не двигайся дальше без явного «ОК» от Ольги** на каждом значимом чекпойнте.
