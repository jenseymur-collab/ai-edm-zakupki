# Промпт: Извлечение структурированных полей из документа

## Назначение

На вход — текст документа закупки (любой из 7 типов) + явный тип документа.
На выход — JSON со структурированными полями.

## Версия

v1 (2026-05-05)

## Модель

`anthropic/claude-sonnet-4.5` через OpenRouter.

## Параметры вызова

```
temperature: 0.0       # детерминированный вывод
max_tokens: 1500
response_format: { type: "json_schema", json_schema: SCHEMA_PER_TYPE }
```

## Системный промпт

```
Ты — ассистент по обработке документов закупки в фармацевтической компании.

Задача: извлечь структурированные данные из текста документа.

Правила:
1. Возвращай только валидный JSON по предоставленной схеме.
2. Если поля нет в тексте — ставь null. Никогда не додумывай.
3. Даты — в формате ISO 8601 (YYYY-MM-DD).
4. Суммы — числом без пробелов и знаков валюты, валюта — отдельным полем.
5. ИНН — строкой, не числом (ведущие нули важны).
6. Если что-то неоднозначно — оставляй null и заполняй поле `неоднозначные_места`.
```

## User-промпт (template)

```
Тип документа: {document_type}

Текст документа:
---
{document_text}
---

Извлеки поля по схеме.
```

## JSON-схемы по типам документов

### Договор

```json
{
  "type": "object",
  "properties": {
    "стороны": { "type": "array", "items": { "type": "string" } },
    "инн_поставщика": { "type": ["string", "null"] },
    "инн_покупателя": { "type": ["string", "null"] },
    "номер": { "type": ["string", "null"] },
    "дата_документа": { "type": ["string", "null"], "format": "date" },
    "сумма": { "type": ["number", "null"] },
    "валюта": { "type": ["string", "null"] },
    "предмет": { "type": ["string", "null"] },
    "мнн_или_субстанция": { "type": ["string", "null"] },
    "срок_оплаты_дни": { "type": ["integer", "null"] },
    "срок_поставки_дни": { "type": ["integer", "null"] },
    "неоднозначные_места": { "type": "array", "items": { "type": "string" } }
  },
  "required": ["стороны", "неоднозначные_места"]
}
```

### Заявка / КП / Протокол / Спецификация / Акт / Счёт-фактура

Аналогичные схемы, специфичные для типа. Полные определения — в коде модуля `ai_извлечение/схемы.py`.

## Тест-фикстуры

См. `тесты/фикстуры/документы/`:
- `договор-полный.txt` → ожидаемый JSON в `договор-полный.json`
- `договор-без-суммы.txt` → ожидаемый JSON с `сумма: null`
- `кп-кратко.txt` → ожидаемый JSON
- `акт-стандарт.txt` → ожидаемый JSON

В тестах сравниваем результат поля за полем, не строгим сравнением строк.

## Метрики качества

- **Точность по полю** = (правильно извлечено) / (всего раз поле было в тексте)
- Цель: ≥ 90% для критичных полей (стороны, ИНН, сумма, дата)
