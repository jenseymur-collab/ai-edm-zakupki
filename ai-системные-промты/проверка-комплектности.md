# Промпт: AI-проверка комплектности сделки

## Назначение

Для конкретной сделки сказать:
1. Комплект документов полный или нет (детерминированно).
2. Есть ли логические нестыковки между документами (через LLM).
3. Что конкретно нужно сделать, чтобы закрыть пробелы.

## Версия

v1 (2026-05-05)

## Модель

`anthropic/claude-sonnet-4.5`

## Этап 1 — детерминированная проверка (без LLM)

Правила:

| Правило | Что проверяем |
|---|---|
| П1. Заявка | Есть документ типа `заявка` со статусом `согласован` |
| П2. КП | ≥ 1 документ типа `кп` |
| П3. Протокол | Есть `протокол_выбора` со статусом `согласован` |
| П4. Договор | Есть активный `договор` со статусом `согласован` |
| П5. Спецификация | Есть `спецификация` для активного договора |
| П6. Акт | Если статус сделки = `закрыта` — есть `акт` |
| П7. Счёт-фактура | Если статус сделки = `закрыта` — есть `счёт_фактура` |

Каждое правило → `OK` / `MISSING` + объяснение.

## Этап 2 — LLM проверяет логические нестыковки

### Системный промпт

```
Ты — аудитор-помощник в фармацевтической компании. Тебе дают извлечённые поля документов одной сделки. Твоя задача — найти логические нестыковки между документами.

Правила:
1. Проверяй: совпадают ли стороны, ИНН, суммы, предметы между связанными документами (договор ↔ спецификация ↔ акт ↔ счёт-фактура).
2. Проверяй: соответствует ли валюта во всех документах.
3. Проверяй: даты идут в логической последовательности (заявка → КП → протокол → договор → спецификация → акт → счёт-фактура).
4. Если нестыковок нет — скажи «нестыковок не выявлено».
5. Если есть — перечисли каждую: что не сходится + между какими документами.
6. Не более 5 пунктов. Только серьёзные расхождения.
```

### User-промпт (template)

```
Сделка: {номер_сделки}, {название_сделки}

Документы и их извлечённые поля:

{для каждого документа}
---
{тип} № {номер} (версия {версия}, статус {статус}):
{извлечённые_поля как list ключ-значение}
---
{/для}

Найди логические нестыковки между этими документами.
```

## Формат ответа frontend-у

```json
{
  "сделка_id": "...",
  "детерминированные_правила": [
    { "правило": "П1", "название": "Заявка", "статус": "OK" },
    { "правило": "П4", "название": "Договор", "статус": "MISSING", "детали": "Нет согласованного договора" }
  ],
  "ai_нестыковки": [
    {
      "тип_проблемы": "сумма",
      "описание": "Сумма в договоре — 1 500 000 RUB, в счёте-фактуре — 1 700 000 RUB.",
      "связанные_документы": ["doc_id_1", "doc_id_2"]
    }
  ],
  "общий_статус": "ATTENTION",   // OK / ATTENTION / BLOCKED
  "рекомендации": [
    "Загрузить согласованный договор (П4)",
    "Сверить сумму в счёте-фактуре с договором"
  ]
}
```

## Логика общего статуса

```
если есть MISSING критичных документов → BLOCKED
иначе если есть AI-нестыковки → ATTENTION
иначе → OK
```

## Тест-фикстуры

`тесты/фикстуры/комплектность/`:
- `сценарий-1-полный-комплект.json` → ожидаем OK
- `сценарий-2-без-договора.json` → BLOCKED
- `сценарий-3-расхождение-суммы.json` → ATTENTION
