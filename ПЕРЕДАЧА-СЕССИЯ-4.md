## Критический баг, исправленный в сессии 3

**Проблема:** Starlette (routing engine FastAPI) использует regex `[a-zA-Z_][a-zA-Z0-9_]*` для имён path-параметров. Кириллица не поддерживается. Маршруты `/{сделка_id}`, `/{документ_id}` регистрировались как **литеральные строки**, не как параметры — отсюда `{"detail":"Not Found"}` на всех карточках.

**Решение:** Переименованы path-параметры в ASCII во всех роутерах:
- `{сделка_id}` → `{deal_id}` в `сделки/роутер.py` и `ai_роутер.py`
- `{документ_id}` → `{doc_id}` в `документы/роутер.py`, `согласование/роутер.py`, `ai_роутер.py`

**Внутренняя логика и переменные остались на кириллице** (ADR не нарушен). Только имена в декораторах и сигнатурах функций изменены.

**Swagger показывал параметры корректно** (FastAPI использует `re.findall(r"\{(.*?)\}")` для OpenAPI), но routing не работал. Это системный gotcha для проектов с кириллическими path-параметрами.

## Технические решения (ADR-summary)

| Решение | Выбор | Причина |
|---|---|---|
| Идентификаторы в Python | **Кириллица** | ADR проекта, читаемость доменного кода |
| Path-параметры роутеров | **ASCII** (deal_id, doc_id) | Ограничение Starlette routing regex |
| LLM-провайдер | **OpenRouter** | Единая точка, смена модели без изменения кода |
| Embeddings | **openai/text-embedding-3-small** | через OpenRouter, 1536 dim |
| Frontend → Backend | **Прямые вызовы** `http://localhost:8000` | Next.js proxy (`/api/*`) нестабильно работал с parameterized routes |
| DB схемы | **5 физических схем PG** | Изоляция доменов, нет cross-schema FK |
