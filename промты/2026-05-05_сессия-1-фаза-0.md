# 2026-05-05 — Сессия 1: Фаза 0, фиксация решений

## Цель сессии

Согласовать ключевые архитектурные решения для MVP AI-системы электронного документооборота закупок и составить план разработки на 1,5 дня.

## Контекст, переданный AI-агенту

1. Профиль Ольги (системный продуктовый лидер с финансовым мышлением, AI-интерес).
2. ТЗ от руководства Ольги — MVP AI-EDM для фарма-закупок.
3. Safety-протокол кодогенерации (правила для AI-агента).

## Ключевые развилки и решения

### 1. Архитектура: микросервисы vs модульный монолит

**Контекст:** Олга сначала склонялась к микросервисам ради масштабируемости.

**Что AI-агент озвучил:**
- Микросервисы добавляют ~7–9 часов налога на инфраструктуру.
- При 36-часовом бюджете и полном скоупе ТЗ это съедает критический запас.
- Модульный монолит даёт ту же масштабируемость в будущем.
- Это паттерн Shopify, Monzo, Stack Overflow.

**Развилка для Ольги:**
- А) Микросервисы → не успеваем + придётся резать скоуп.
- Б) Модульный монолит → успеваем с полным скоупом.

**Решение:** Модульный монолит при полном скоупе ТЗ. См. ADR-0003.

### 2. LLM-провайдер

**Контекст:** Изначально обсуждали Anthropic API напрямую.

**Что выяснилось:**
- Аккаунт Ольги — на Claude.ai (это подписка, не API).
- Для Anthropic API нужна отдельная регистрация на console.anthropic.com.
- С российской карты Anthropic не работает.
- У Ольги есть API-ключ OpenRouter с балансом $90.

**Решение:** OpenRouter. Один ключ — все модели (Claude, OpenAI, embeddings). См. ADR-0002.

### 3. Распределение моделей

**Контекст:** Изначально Олга хотела использовать Opus везде («самую передовую»).

**Что AI-агент озвучил:**
- Opus на всех вызовах = $50–100, на грани её $90 бюджета.
- Sonnet 4.5 даёт качество Opus на структурированных задачах при 5x меньшей цене.
- Для рассуждений (сравнение версий договоров) Opus оправдан.

**Решение:** Гибрид. Sonnet 4.5 — основная масса вызовов. Opus 4.6 — только сравнение версий договоров. См. ADR-0002.

### 4. Стек

**Решение:** Python (FastAPI + SQLAlchemy + Pydantic) + Next.js + Tailwind + PostgreSQL+pgvector. См. ADR-0001.

### 5. Модель работы

- AI-агент пишет код, Ольга ревьюит и запускает.
- Ольга — не разработчик, AI-агент разжёвывает каждый шаг.
- Перенос в GitHub — через GitHub Desktop (у Ольги установлен).

### 6. Скоуп

Сохранён полный по ТЗ:
- 7 типов документов
- Связи и единая карточка сделки
- Workflow согласования
- Версионирование с diff
- Семантический поиск
- AI-извлечение полей
- Анализ задержек
- Проверка комплектности
- Сравнение версий договора (с AI-комментарием)
- Дашборд
- Граф связей документов

Мобильный UI и реальная авторизация — вне скоупа MVP, упомянуты в README как next steps.

## Подход к работе с AI-агентом

Ольга в профиле обозначила:
- Любит интеллектуальную честность.
- Не принимает поверхностных объяснений.
- Любит структуру и системное мышление.

Следствие для AI-агента:
- Не соглашаться рефлекторно — пушбэк, когда видим, что решение проблемное.
- Объяснять «почему», а не только «как».
- Заземлять абстрактное в цифры (часы, $, токены).
- Каждый шаг кодогенерации сопровождать explicit-проверкой по safety-протоколу.

## Что важно не забыть на следующих фазах

- На Фазе 1 проверить точные имена моделей в каталоге OpenRouter.
- На Фазе 5 решить вопрос с хостингом (Railway / Render / Fly.io) — пока не зафиксирован.
- В дашборде Фазы 5 добавить счётчик расхода токенов.
- При приближении к $70 расхода — переключить флаг с Opus на Sonnet даже на сравнении версий.
