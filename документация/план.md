## Что добавилось после ревью Ольги (важное)

### 1. Async-обработка AI-вызовов (Фаза 3)
Загрузка документа в БД и AI-обработка **разъединены**. Документ всегда сохраняется первым; AI-вызов в `try/except`. При ошибке статус документа = `ai_ожидает_повтора`. Кнопка «переизвлечь» в UI.

### 2. Postgres-схемы на модуль (Фаза 1)
Каждый модуль владеет своей схемой: `документы.*`, `сделки.*`, `согласование.*`. Cross-schema joins запрещены архитектурно.

### 3. Events log (Фаза 2)
Append-only таблица `события` (журнал аудита). Каждый мутирующий эндпоинт пишет событие через middleware. Вкладка «История» в карточке сделки — добавляется в Фазу 4.

### 4. Нормализация статусов (Фаза 2)
Разнесены: `документ.статус`, `маршрут.статус`, `шаг.статус`, `виза.решение`. Подробно в `модель-данных.md`.

### 5. content_hash + источник (Фаза 2)
SHA-256 текста + источник (`web_paste` / `api`). Защита от дублей.

### 6. Профили сделки (Фаза 2)
Поле `сделка.профиль`: `стандарт` (7 документов) / `малая_закупка` (5 документов без протокола и спецификации). Влияет на проверку комплектности.

### 7. Версия маршрута + версия схемы извлечения
Поля `маршрут.версия`, `маршрут.активен`, `extracted_fields.схема_версия` — для будущей эволюции без миграций.

### 8. jsonb-условия в маршрутах
Поле `маршрут.условия_jsonb` для будущих критериев. В MVP оцениваются только сумма+тип.

### 9. Fallback на сравнении версий (Фаза 3)
Если Opus тормозит / превышает квоту — деградируем до Sonnet с упрощённым описанием изменений без риск-классификатора.

### 10. Один «грязный» документ в Сделке Б
Демонстрирует fallback при ошибке AI-извлечения.

## Фаза 3 — AI-слой (8 часов)

### Принцип fault tolerance

**Каждый AI-вызов** обёрнут в:
1. Сохраняем сначала, AI-вызов потом
2. `try/except` с конкретными типами исключений (timeout, rate_limit, json_parse_error)
3. При ошибке: статус = `ai_ожидает_повтора`, исходные данные сохранены
4. Логируем в `события` факт сбоя

### 6 функций (порядок выполнения)

1. **Извлечение полей** (Sonnet 4.5) — 1.5 ч
2. **Эмбеддинги и индексация** (text-embedding-3-small) — 1 ч
3. **Семантический поиск** (Sonnet 4.5) — 1.5 ч
4. **Анализ задержек** (Sonnet 4.5) — 1.5 ч
5. **Аудит комплектности** (Sonnet 4.5) — учитывает профиль сделки — 1 ч
6. **Сравнение версий договора** (Opus 4.6) — 1.5 ч
   - **Fallback:** если Opus превышает квоту/тайминг → Sonnet с упрощённым выводом
