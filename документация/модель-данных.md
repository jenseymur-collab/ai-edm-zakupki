# Модель данных AI-EDM Закупки (v2 — после ревью Ольги)

## Что изменилось в v2

- Добавлена сущность `события` (audit trail)
- Нормализованы статусы: `документ`, `маршрут`, `шаг`, `виза` имеют свои статусы
- Добавлены поля: `content_hash`, `источник`, `профиль` сделки, `схема_версия` извлечения, `версия` маршрута, `условия_jsonb`
- Каждая сущность размещена в Postgres-схеме своего модуля (`документы.*`, `сделки.*`, `согласование.*`, `аудит.*`)

## Размещение по схемам

```
сделки.сделки
сделки.поставщики
документы.документы
документы.extracted_fields
документы.embeddings
согласование.approval_routes
согласование.approval_route_steps
согласование.approvals
аудит.события
пользователи.пользователи
```

Cross-schema joins **запрещены** архитектурным линтером. Если модулю А нужны данные модуля Б — он зовёт публичный API модуля Б.

## Логика создания версий документа

При загрузке документа того же типа в ту же сделку:

1. Вычисляем `content_hash` входного текста.
2. Если `(сделка_id, тип, content_hash)` уже есть → 409 «такой документ уже загружен».
3. Иначе:
   - Найти текущий активный документ этого типа в этой сделке.
   - Если найден: поставить ему `активная = false`, `статус = архив`. Записать событие `документ.архивирован`.
   - Создать новый документ: `версия = старая + 1`, `родитель_id = старая.id`, `активная = true`, `статус = загружен`.
   - Записать событие `документ.загружен`.
   - Запустить (с try/except) AI-извлечение и эмбеддинг.
   - При успехе: `статус = на_согласовании` (если есть маршрут).
   - При ошибке AI: `статус = ai_ожидает_повтора`, событие `документ.ai_ошибка`.

## Логика выбора маршрута согласования

```
1. Найти activeapproval_routes где:
   - тип_документа = тип документа
   - сделка.сумма попадает в [сумма_от, сумма_до]
   - активен = true
2. Если несколько — взять самый специфичный.
3. Если не найдено — статус «не_требует_согласования», событие `документ.без_маршрута`.
4. Создать визы-заглушки для каждого шага.
5. Активный шаг = первый по порядку.
```

## Просрочки

```
для активного шага:
  start = max(предыдущая виза.решено_когда, документ.загружен_когда)
  если now() - start > шаг.срок_дни → просрочка
```

## Полнота сделки (учёт профиля)

```
required_types = {
  "стандарт": [заявка, кп, протокол_выбора, договор, спецификация, акт, счёт_фактура],
  "малая_закупка": [заявка, кп, договор, акт, счёт_фактура]
}[сделка.профиль]

для каждого type в required_types:
   проверить наличие активного документа со статусом «согласован»

детерминированный_статус = OK / MISSING

затем — AI-проверка нестыковок (см. промпт `проверка-комплектности.md`)

общий_статус = OK / ATTENTION / BLOCKED
```
