# Документация

Архитектура, решения, инструкции.

## Что лежит здесь

- `план.md` — план разработки по фазам (появится после Фазы 0)
- `архитектура.md` — компоненты системы, потоки данных, схема БД
- `модель-данных.md` — описание сущностей и связей
- `api.md` — описание эндпоинтов
- `решения/` — ADR (Architecture Decision Records). По одной записи на каждое значимое архитектурное решение

## ADR — зачем

Когда мы будем выбирать стек, провайдера LLM, способ хранения файлов и т.д. — каждое такое решение фиксируется в `решения/NNNN-название.md` по шаблону:

```
# ADR-0001: Выбор LLM-провайдера

## Контекст
Что нас вынудило принимать это решение

## Варианты
- А: ...
- Б: ...
- В: ...

## Решение
Выбран вариант Б, потому что ...

## Последствия
+ ...
- ...
```

Это даст возможность через 3 дня вспомнить **почему** мы что-то сделали именно так — критично для аудита и для рефлексии.
