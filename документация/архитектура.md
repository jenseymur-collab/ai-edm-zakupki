## Поток данных при загрузке документа

```
Пользователь вставляет текст договора
       │
       ▼
[Frontend] POST /api/документы { сделка_id, тип, текст }
       │
       ▼
[документы.роуты] валидация → [документы.сервис]
       │
       ▼
[документы.сервис]
   1. Сохраняет документ в БД (статус: «загружен»)
   2. Создаёт новую версию (если документ того же типа уже есть)
   3. Вызывает [ai_извлечение.сервис].извлечь_поля(текст, тип)
       │
       └─► [llm_client] → OpenRouter (Claude Sonnet)
              │
              └─► JSON с полями
   4. Сохраняет извлечённые поля в БД
   5. Вызывает [ai_поиск.сервис].индексировать(документ_id, текст)
       │
       └─► [llm_client] → OpenRouter (text-embedding-3-small)
              │
              └─► вектор
   6. Сохраняет вектор в pgvector
   7. Возвращает документ_id + извлечённые поля
       │
       ▼
[Frontend] показывает документ с распарсенными полями
```

## Поток данных при семантическом поиске

```
Пользователь вводит «договор с Pharma Corp на парацетамол»
       │
       ▼
[Frontend] GET /api/поиск?запрос=...
       │
       ▼
[ai_поиск.роуты] → [ai_поиск.сервис]
       │
       ├─► [llm_client].embed(запрос) → вектор запроса
       │
       ├─► [ai_поиск.репозиторий].найти_похожие(вектор, top_k=5)
       │      └─► pgvector cosine similarity → 5 документов
       │
       ├─► [llm_client].chat(контекст=документы, запрос=запрос)
       │      └─► Claude Sonnet формирует ответ
       │
       └─► возвращает: { документы: [...], ai_ответ: "..." }
       │
       ▼
[Frontend] показывает результаты + AI-ответ
```

## Поток данных при согласовании

```
Пользователь нажимает «Согласовать» на документе
       │
       ▼
[Frontend] POST /api/согласование/визы { документ_id, шаг_id, решение }
       │  Заголовок Idempotency-Key (UUID)
       ▼
[согласование.роуты] → [согласование.сервис]
       │
       ├─► Проверка: эта виза уже была? (по Idempotency-Key)
       │     └─► если да → возвращаем существующий результат
       │
       ├─► Сохранение визы в БД
       │
       ├─► Проверка: маршрут завершён?
       │     └─► если да → меняем статус документа на «согласован»
       │     └─► если нет → активируем следующий шаг
       │
       └─► возвращает обновлённый статус документа
       │
       ▼
[Frontend] обновляет UI
```

## Принципы взаимодействия модулей

1. **Один модуль не лезет в БД другого модуля.** Если модулю А нужны данные из модуля Б — он вызывает функцию из публичного API Б.

2. **Все вызовы LLM — только через `общее/llm_client.py`.** Модули не знают, какой провайдер используется и как конкретно делается запрос.

3. **Все DTO — Pydantic.** Никаких dict-ов для данных, которые пересекают границы.

4. **Все ошибки — типизированы.** В `общее/ошибки.py` иерархия исключений; HTTP-обработчики мапят их в коды ответов.

5. **Логирование централизовано.** Структурные логи (JSON) с trace_id, привязанным к запросу.

## Безопасность и обработка ошибок

| Слой | Что обрабатывает |
|---|---|
| Frontend | Сетевые ошибки, отображение пользовательских сообщений |
| API Middleware | Глобальный exception handler → JSON-ошибки с понятным сообщением |
| Сервисный слой | Бизнес-исключения (ValidationError, NotFoundError, ConflictError) |
| Репозиторий | DB-исключения → ConflictError для уникальных нарушений |
| LLM-клиент | Timeout, rate limit, JSON-parse error → fallback («ручная проверка») |

## Развёртывание

### Локально (разработка)

```
docker-compose up
```

Поднимает:
- backend на :8000
- postgres+pgvector на :5432
- frontend через `npm run dev` на :3000 (отдельно)

### Production (деплой)

Будет выбран в Фазе 5 (ADR-0004 при старте). Кандидаты: Railway / Render / Fly.io.

Структура:
- backend + postgres → одна машина у выбранного провайдера
- frontend → Vercel (статика + serverless)
- секреты → environment variables, никогда не в репозитории

## Ограничения архитектуры (честно)

| Ограничение | Почему | Что с этим делать |
|---|---|---|
| Общая БД для всех модулей | Альтернатива требует репликации, не успеем | Принято для MVP; в README указано как «техдолг» |
| Все вызовы LLM синхронные | Очередь требует Redis+воркер, не успеем | Принято для MVP; deer-документы лимитированы по размеру |
| Mock-авторизация | Реальная требует SSO/OAuth | Принято для MVP; в README указано |
| Один процесс backend | Масштабирование требует балансировки | Не критично для MVP |
