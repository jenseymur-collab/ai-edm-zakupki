# ADR-0001: Выбор технологического стека

**Дата:** 2026-05-05
**Статус:** Принято
**Автор:** AI-агент + Ольга

## Контекст

Нужно выбрать стек для MVP за 1,5 дня. Ограничения:
- Ольга — ревьюер, не разработчик. Стек должен быть читаемым.
- Полная свобода выбора по ТЗ.
- AI-функции через OpenRouter (см. ADR-0002).
- Деплой обязателен.

## Варианты

### А. Python (FastAPI) backend + Next.js frontend
- **Плюс:** FastAPI — самый ясный для нетехнического ревью Python-фреймворк (декораторы + типизация).
- **Плюс:** Pydantic закрывает требование safety-протокола о явных DTO.
- **Плюс:** OpenRouter работает через стандартный OpenAI SDK на Python — обширно документирован.
- **Плюс:** Зрелый pgvector интегрирован с SQLAlchemy.
- **Минус:** Два языка в проекте (Python + TypeScript). Но это де-факто стандарт для full-stack.

### Б. Node.js (Express/NestJS) backend + Next.js frontend
- **Плюс:** Один язык на весь стек.
- **Минус:** В TS сложнее писать AI-вызовы — экосистема для LLM беднее, чем у Python.
- **Минус:** Pydantic-аналог (Zod) не так строго работает на runtime.

### В. Full-stack Next.js (API routes)
- **Плюс:** Один проект, один деплой.
- **Минус:** API routes не подходят для длинных AI-операций (timeout, изоляция).
- **Минус:** Сложно писать модульный монолит — Next.js навязывает свою структуру.

## Решение

**Вариант А: Python (FastAPI) + Next.js.**

## Стек целиком

| Слой | Технология | Версия | Зачем |
|---|---|---|---|
| Backend framework | FastAPI | 0.115+ | API + автодокументация Swagger |
| Validation | Pydantic v2 | 2.9+ | Явные DTO (требование safety) |
| ORM | SQLAlchemy | 2.x async | БД-операции |
| Migrations | Alembic | latest | Миграции схемы |
| Database | PostgreSQL | 16 | Основное хранилище |
| Vector search | pgvector | 0.7+ | Семантический поиск |
| LLM client | OpenAI SDK | latest | OpenRouter совместим с OpenAI API |
| HTTP client | httpx | latest | Внутренние вызовы (если понадобятся) |
| Testing | pytest + pytest-asyncio | latest | Тесты |
| Frontend framework | Next.js | 15.x | UI |
| Frontend styling | Tailwind CSS | 3.x | Быстрая стилизация |
| Frontend state | TanStack Query | 5.x | Запросы к API |
| Frontend graphs | Mermaid | latest | Граф связей документов |
| Containers | Docker + docker-compose | latest | Локальный запуск |
| CI | GitHub Actions | — | Lint + тесты на каждый push |

## Последствия

**Положительные:**
- Все технологии — индустриальный стандарт. Ольга после проекта может показать стек на собеседовании.
- Каждая зависимость хорошо документирована.
- Все автоматические проверки (pyright/mypy, eslint, тесты) дают защиту от тех ошибок, которые safety-протокол ловит вручную.

**Отрицательные:**
- Два языка — двойная установка зависимостей при локальном запуске. Решается через docker-compose: одной командой поднимается всё.
- Нет Yandex Cloud / GigaChat в списке. Если понадобится локализация на РФ — придётся пересматривать (но OpenRouter работает откуда угодно).

## Что не пробуем

- Django (тяжелее FastAPI на старте)
- Flask (нет нативной async, нет Pydantic, нет автодоков)
- Vue/Nuxt (Олге показывать React-Next ближе по индустрии)
