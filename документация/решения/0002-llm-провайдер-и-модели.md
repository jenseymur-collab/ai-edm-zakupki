# ADR-0002: LLM-провайдер и выбор моделей

**Дата:** 2026-05-05
**Статус:** Принято
**Автор:** AI-агент + Ольга

## Контекст

Нужен LLM-провайдер для:
- извлечения полей из документов (большой объём вызовов)
- семантического поиска (embeddings + RAG-ответы)
- анализа задержек согласования
- аудита комплектности сделки
- сравнения версий договора (требует более глубоких рассуждений)

Ограничения:
- Бюджет: $90 (OpenRouter limit)
- Срок: 1,5 дня
- Качество критично — это фарма-документооборот

## Варианты провайдера

### А. Anthropic API напрямую
- **Плюс:** минимальная latency, максимальное качество Claude.
- **Минус:** требует регистрацию на console.anthropic.com и зарубежную карту.

### Б. OpenAI API напрямую
- **Плюс:** работает с зарубежной карты, embeddings нативные.
- **Минус:** нет Claude (Олга предпочитает Anthropic).

### В. OpenRouter
- **Плюс:** один ключ — все модели (Claude, OpenAI, Voyage, и др.).
- **Плюс:** работает откуда угодно, без проблем с картами.
- **Плюс:** можно менять модель одной строкой кода.
- **Минус:** +5–10% к цене провайдера, +100–300мс latency.

## Решение

**Вариант В: OpenRouter.**

У Ольги уже есть API-ключ с балансом $90, и это решение убирает все вопросы с регистрацией и картами.

## Распределение моделей по задачам

Гибрид Sonnet/Opus — компромисс «качество × бюджет».

| Задача | Модель | Почему |
|---|---|---|
| Извлечение полей из документов | `anthropic/claude-sonnet-4.5` | Структурированный вывод — Sonnet даёт качество Opus при ~5x меньшей цене и ~2x быстрее |
| Семантический поиск (RAG-ответ) | `anthropic/claude-sonnet-4.5` | Ответы по контексту, без сложных рассуждений |
| Анализ задержек | `anthropic/claude-sonnet-4.5` | Простой анализ + рекомендация |
| Аудит комплектности | `anthropic/claude-sonnet-4.5` | Сверка по правилам + объяснение |
| **Сравнение версий договора** | `anthropic/claude-opus-4.6` | Тут реально нужны рассуждения и оценка рисков |
| Эмбеддинги | `openai/text-embedding-3-small` | Самые дешёвые, многоязычные, через OpenRouter |

**Точные имена моделей в OpenRouter каталоге сверим в Фазе 1 — синтаксис может отличаться.**

## Архитектурные принципы вызовов LLM

Каждый вызов LLM в коде обёрнут в:
- timeout (30 сек)
- retry (макс 2 раза, экспоненциальный backoff)
- fallback («не удалось извлечь — пометь документ как требующий ручной проверки»)
- логирование (запрос, ответ, токены, время)
- проверку формата ответа (JSON-schema validation)

В тестах LLM **замокан** — никогда не дёргаем реальное API из тестов.

## Мониторинг бюджета

В Фазе 5 добавим в дашборд счётчик «токенов потрачено за сегодня» из OpenRouter API. Если приближаемся к $70 — Olga переключает Opus → Sonnet ручным флагом в `.env`.

## Последствия

**Положительные:**
- Один ключ, один SDK (OpenAI), все модели доступны.
- Можно менять модель без переписывания кода.
- Бюджет с запасом 5–10x.

**Отрицательные:**
- Зависимость от OpenRouter как промежуточного слоя. Если упадёт — упадут все AI-функции. Митигация: код абстрагирован за `LLMClient`, замена провайдера = замена 1 файла.
- +100–300мс latency на каждом вызове. Для нашего MVP некритично.
