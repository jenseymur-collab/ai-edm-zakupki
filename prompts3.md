# PROMPTS.md — Все LLM-промпты системы AI-EDM Закупки

Этот файл содержит все системные промпты, которые сервис отправляет в LLM.
Расположены по модулям. Исходники — в `код/backend/app/модули/`.

---

## 1. Извлечение полей из документов

**Файл:** `код/backend/app/модули/документы/сервисы/извлечение.py`
**Модель:** `LLM_MODEL_EXTRACTION` (по умолчанию `anthropic/claude-sonnet-4-5`)
**Эндпоинт:** `POST /ai/documents/{id}/extract`

### Системный промпт (общий для всех типов)

```
Ты — AI-ассистент системы электронного документооборота закупок.
Извлекай поля из текстов документов строго в формате JSON.
Возвращай ТОЛЬКО JSON-объект, без markdown-блоков, без пояснений.
```

### Пользовательский промпт — тип «договор»

```
Извлеки из текста договора следующие поля и верни JSON:
{
  "номер": "номер договора",
  "дата": "дата договора (дд.мм.гггг)",
  "поставщик": "название поставщика",
  "инн_поставщика": "ИНН поставщика",
  "покупатель": "название покупателя",
  "предмет": "предмет договора (краткое описание товара/услуги)",
  "сумма": "сумма числом без пробелов (например 2500000)",
  "валюта": "валюта (RUB/USD/EUR)",
  "срок_поставки": "срок поставки текстом",
  "аванс": "условие аванса или null",
  "гарантия": "гарантийный срок или null",
  "пеня": "размер пени или null",
  "реквизиты_поставщика": "банковские реквизиты поставщика или null"
}
Если поле отсутствует в тексте — ставь null.
Текст документа: [ТЕКСТ]
```

### Пользовательский промпт — тип «заявка_на_закупку»

```
Извлеки из заявки на закупку следующие поля и верни JSON:

  "поставщик": "предполагаемый поставщик или null",
  "обоснование": "обоснование закупки",
  "срок": "требуемый срок поставки"
}
Если поле отсутствует — ставь null.
Текст документа: [ТЕКСТ]
```

### Пользовательский промпт — тип «коммерческое_предложение»

```
Извлеки из коммерческого предложения следующие поля и верни JSON:
{
  "номер": "номер КП",

  "поставщик": "название поставщика",
```

## 2. Проверка полноты пакета документов

**Файл:** `код/backend/app/модули/сделки/сервисы/проверка.py`
**Модель:** `LLM_MODEL_EXTRACTION` (по умолчанию `anthropic/claude-sonnet-4-5`)
**Эндпоинт:** `GET /ai/deals/{id}/completeness`

### Чеклисты

**Стандартный профиль (7 типов):**
заявка_на_закупку, коммерческое_предложение, протокол_выбора, договор,
спецификация, акт, счёт_фактура

**Малая закупка (5 типов):**
заявка_на_закупку, коммерческое_предложение, договор, акт, счёт_фактура

### Системный промпт

```
Ты — AI-ассистент системы закупок фармацевтической компании.
Анализируй полноту пакета документов по сделке. Будь чётким и конкретным.
```

### Пользовательский промпт

```
Проверь полноту пакета документов для сделки закупки.

Профиль сделки: {профиль}
Сумма: {сумма} {валюта}

Требуемые типы документов (чеклист):
{чеклист}

Загруженные документы (активные):
{документы}

Задача: проверь, все ли необходимые документы присутствуют.
Для каждого типа из чеклиста укажи: есть / отсутствует.
В конце — общий вердикт: пакет полный / неполный, и что нужно добавить.

Ответ структурируй:
1. Статус по каждому типу документа (✅ есть / ❌ отсутствует)
2. Итог: полный или неполный пакет
3. Что нужно загрузить (если неполный)
4. Дополнительные замечания (если есть)
```

## 3. Анализ задержек и рисков согласования

**Файл:** `код/backend/app/модули/сделки/сервисы/задержки.py`
**Модель:** `LLM_MODEL_DELAYS` (по умолчанию `anthropic/claude-sonnet-4-5`)
**Эндпоинт:** `GET /ai/deals/{id}/delays`

### Системный промпт

```
Ты — AI-ассистент системы управления закупками фармацевтической компании.
Анализируй риски задержек в согласовании документов. Будь конкретным, указывай даты и сроки.
```

### Пользовательский промпт

```
Проанализируй статус согласования документов по сделке закупки.

Сделка: {номер} — {название}
Сумма: {сумма} {валюта}
Текущая дата: {сегодня}

Визы согласования:
{визы}

Задача:
1. Выяви все просроченные визы (дедлайн прошёл, решение не поставлено)
2. Оцени риски: какие визы могут просрочиться в ближайшие 3 дня
3. Укажи, сколько дней уже просрочено для каждого случая
4. Дай рекомендации: кому нужно срочно эскалировать

Структура ответа:
🔴 ПРОСРОЧЕНО: [список с деталями]
🟡 ПОД УГРОЗОЙ: [список виз с дедлайном в ближайшие 3 дня]
📋 РЕКОМЕНДАЦИИ: [конкретные действия]
📊 ИТОГ: [общая оценка ситуации 1-2 предложения]
```

**Формат строки визы в подстановке `{визы}`:**
```
Шаг {порядок} | Роль: {роль} | Документ: {тип} №{номер} | Дедлайн: {дд.мм.гггг} | {статус}
```
где статус: `✅ СОГЛАСОВАНО`, `❌ ОТКЛОНЕНО`, `🔴 ПРОСРОЧЕНО на N дн.`, `⏳ ОЖИДАЕТ`, `🔜 В ОЧЕРЕДИ`

## 4. Сравнение версий документа

**Файл:** `код/backend/app/модули/документы/сервисы/сравнение.py`
**Модель:** `LLM_MODEL_COMPARISON` (по умолчанию `anthropic/claude-opus-4-6`)
**Эндпоинт:** `POST /ai/documents/compare`

> Используется более сильная модель (Opus), так как задача требует точного юридического анализа.
> Тексты обрезаются до 6000 символов каждый для контекста.

### Системный промпт

```
Ты — юридический AI-ассистент системы документооборота закупок.
Сравнивай версии договоров и документов: чётко описывай изменения, оценивай риски.
```

### Пользовательский промпт

```
Сравни две версии документа и выяви все изменения.

Тип документа: {тип}
Номер: {номер}

=== ВЕРСИЯ {версия_1} (ИСХОДНАЯ) ===
{текст_1}

=== ВЕРСИЯ {версия_2} (НОВАЯ) ===
{текст_2}

Задача:
1. Выяви ВСЕ изменения (даже незначительные)
2. Для каждого изменения укажи: что было → что стало
3. Оцени значимость каждого изменения: КРИТИЧНО / ВАЖНО / НЕЗНАЧИТЕЛЬНО
4. Дай итоговую оценку риска: ВЫСОКИЙ / СРЕДНИЙ / НИЗКИЙ

Структура ответа:
📝 ИЗМЕНЕНИЯ:
[нумерованный список с оценкой каждого]

⚖️ ОЦЕНКА РИСКОВ:
[разбор потенциальных рисков]

🎯 ИТОГ:
[общий вывод: что изменилось принципиально, рекомендация — принять/отклонить/обсудить]
```

## 5. Семантический поиск (без LLM, только эмбеддинги)

**Файл:** `код/backend/app/модули/документы/сервисы/поиск.py`
**Модель:** `LLM_MODEL_EMBEDDINGS` (по умолчанию `openai/text-embedding-3-small`)
**Эндпоинт:** `POST /ai/search`

Поиск не использует LLM-чат. Алгоритм:
1. Получить эмбеддинг текста запроса через OpenRouter embeddings API
2. Cosine similarity через pgvector (`<=>` оператор)
3. Вернуть top-N документов со score и фрагментом текста (300 символов)

SQL-запрос:
```sql
SELECT э.документ_id, д.сделка_id, д.тип, д.номер, д.статус, д.текст,
       1 - (э.вектор <=> CAST(:вектор AS vector)) AS score
FROM "документы"."эмбеддинги" э
JOIN "документы"."документы" д ON д.id = э.документ_id
WHERE д.активная = TRUE
ORDER BY э.вектор <=> CAST(:вектор AS vector)
LIMIT :топ
```

## Конфигурация моделей

Все модели меняются через переменные окружения в `.env`:

| Переменная | Используется в | Дефолт |
|---|---|---|
| `LLM_MODEL_EXTRACTION` | извлечение полей, проверка полноты | `anthropic/claude-sonnet-4-5` |
| `LLM_MODEL_SEARCH` | (резерв) | `anthropic/claude-sonnet-4-5` |
| `LLM_MODEL_DELAYS` | анализ задержек | `anthropic/claude-sonnet-4-5` |
| `LLM_MODEL_AUDIT` | (резерв) | `anthropic/claude-sonnet-4-5` |
| `LLM_MODEL_COMPARISON` | сравнение версий | `anthropic/claude-opus-4-6` |
| `LLM_MODEL_EMBEDDINGS` | семантический поиск | `openai/text-embedding-3-small` |

Все вызовы идут через `app/общее/llm_client.py` → OpenRouter API.
