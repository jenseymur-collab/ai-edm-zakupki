# Safety

Стандарт качества кодогенерации + чек-листы. Здесь живёт «договор о качестве кода» между Ольгой и AI-агентом.

## Что лежит

- `протокол.md` — основной протокол кодогенерации (исходный документ Ольги)
- `чек-лист-перед-коммитом.md` — короткий чек-лист, который AI прогоняет перед выдачей кода
- `критические-условия-сбоя.md` — что считается невалидным ответом

## Ключевые принципы

> Code correctness > speed
> Architecture safety > completeness
> Verifiability > elegance

## Как применяем на практике

1. **Перед** генерацией кода AI явно проговаривает контекст: какой сервис, какой слой, какие границы данных.
2. **Во время** — все DTO явные, все импорты реальные, никаких placeholder-ов.
3. **После** — AI сам прогоняет 4 проверки (синтаксис, логика, архитектура, runtime simulation) и выдаёт результат в формате: код + объяснение + риски + чек-лист для Ольги.
4. **Если AI не уверен** — явно говорит об этом и даёт несколько альтернатив, не выдумывая API.

## Зачем это вообще

Без такого протокола LLM сваливается в правдоподобный, но нерабочий код:
- импорты несуществующих пакетов
- методы, которых нет в библиотеке
- архитектурные нарушения, которые видны только в проде
- скрытые предположения, которые ломаются на втором тесте

Цена ошибки в фарма-системе документооборота — не «упал сайт», а «потерян документ при аудите». Поэтому планка выше обычной.
