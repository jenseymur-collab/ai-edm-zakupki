# Тесты

Автотесты, проверяющие код на работоспособность.

## Уровни тестирования

```
тесты/
├── unit/           # изолированные модули (без внешних вызовов)
├── integration/    # связки сервис ↔ БД, сервис ↔ LLM (с моками)
└── e2e/            # сквозные сценарии через API/UI
```

## Что обязательно покрываем (минимум для MVP)

### Unit
- Извлечение полей из текста договора (на фикстурах с известными значениями)
- Логика маршрутов согласования (по типу + сумме)
- Версионирование (новая версия → старая архивируется)
- Проверка комплектности сделки (детерминированные правила)

### Integration
- Загрузка документа → embedding → запись в pgvector
- Семантический поиск возвращает ожидаемые документы
- Согласование idempotent (повторный вызов не дублирует визу)

### E2E (smoke)
- Создать сделку → загрузить все 7 документов → пройти согласование → дашборд показывает «комплектация 100%»

## Принципы

- LLM в тестах **замоканы** (не жжём токены и не зависим от сети).
- Фикстуры документов — в `тесты/фикстуры/` (несколько договоров, КП, актов с известными полями).
- Тесты должны проходить за < 30 секунд — иначе их перестанут гонять.
